# R05 compiler diagnostics

Implemented 16 October 2026 (Asia/Bangkok), after R04 was reviewed and merged in PR #13. Review and final-head CI are required before merging this increment.

## Design

`CompilerDiagnostics` parses bounded Tectonic output into error/warning severity, categories, explanations, optional file/line and nearby multiline compiler text. The actual compiler's `main.tex:line` messages support unknown commands, missing images/files and overfull boxes; fixtures also cover missing fonts/glyphs, unfamiliar messages, invalid line numbers and ANSI sequences. Line-less messages retain their text and raw-log access without guessed locations or fixes. A failed build without a recognizable error receives an explicit location-less failure entry. The parser reads 64 KiB and emits at most 200 diagnostics; each limit is reported independently.

After each build, the service atomically replaces a diagnostics snapshot containing the compiled revision, result, structured items and the bounded original log. Source saving does not relabel that snapshot. Logs are cleared before launching a new run so launch failures cannot inherit older output. The service reconciles interrupted completion metadata with the failed job status. Legacy, corrupt or missing snapshot metadata produces an unknown revision, which cannot navigate. The raw-log endpoint uses the same retained snapshot and adds a visible truncation marker; full tool output remains in project storage as `preview.log`.

The diagnostics panel is available across Source, Preview and Review. It distinguishes a failed build from a successful build with warnings. Only exact `main.tex` or `./main.tex` locations can offer navigation; package/absolute/traversal paths remain plain text. Unsaved changes, changed saved revisions, unknown attribution, unavailable source and loading failures disable navigation. App rechecks current document/revision/readiness at reveal time; R04's editor then focuses and reveals the line without changing source. Requests are aborted when document/build identity changes.

A gated successful-build response proves that the prior failure/old navigation is hidden, and an actual compiler retry with an unusable log path proves prior same-revision attribution is removed. After these fixes, all 12 focused desktop/mobile diagnostic workflows and all five focused parser/actual-compiler checks passed again; final-head CI reruns the full suites.
