# R06 guided conversion review

Implemented 16 October 2026 (Asia/Bangkok), after R05 was reviewed and merged in PR #15. Validation is in progress; completed review and final-head CI remain required before merging.

Implement stable occurrence IDs and bounded original excerpts, conservative source locations, and persisted review decisions in one focused ticket PR. Initial risks are merged tables, numbered captions, headers/footers and tracked changes. The original-text comparison is a text/structure aid, not a Word page renderer or a fidelity score.

Use secure namespace-aware XML parsing with external entities/DTDs disabled and explicit decompressed-byte, paragraph, excerpt and finding bounds. Preserve repeated occurrences as separate findings. Navigation requires a unique original anchor and unique escaped-text match in source; merged-table anchors must belong to a recognized table environment. Ambiguous, omitted, truncated and absent text receives an unavailable-location explanation.

Bounds are 32 XML parts, 2 MiB per part / 8 MiB decompressed total, 128 element levels, 500 paragraphs, 65,536 original-text characters, 100 finding occurrences, 2,048 characters per paragraph and 1,200 per displayed finding excerpt. Clipping preserves Unicode surrogate pairs. Header/footer text receives the text budget before long body content. Any limited inspection disables mappings conservatively. XML depth configuration follows the [Java 21 JAXP properties](https://docs.oracle.com/en/java/javase/21/docs/api/java.xml/module-summary.html); it is tested with a document exceeding the configured depth and with an external-entity declaration.

User decisions live separately from detected risks. Their evidence fingerprint includes the immutable original finding identity and the entire mapped source paragraph/table/figure region. An unchanged mapped region may carry a decision across source revisions; any changed region requires review again. An unmapped finding includes the source revision in its fingerprint and never carries across a revision. This rule is conservative and explicit; marking reviewed never removes a warning.

Persist decisions atomically under the job lifecycle lease, with current-revision/fingerprint checks and safe failure behavior for damaged metadata. Export detected risks, original excerpts/mappings, decisions and applicable revision distinctly. Check inspector, mapping, persistence/restart and browser comparison workflows, then full Windows/Linux/PDF verification and completed review before merge.

Decision writes also require verified saved-source integrity; original excerpts remain readable if history/source fails, while decisions stay unchanged. Metadata is bounded, versioned, forced to disk before atomic publication, and followed by directory forcing where supported. Damaged decision metadata disables editing those decisions instead of replacing it. Review responses and decision results are fenced by document/revision/build request identity. Unsaved edits disable decisions/navigation and explicitly label decisions as describing saved source.

The Review tab loads on demand (about 6.18 kB minified / 2.13 kB gzip); the initial app chunk is about 493.27 kB / 146.82 kB gzip without Vite bundle warnings. Original text sits beside source/PDF on wider desktop layouts and stacks on mobile/tablet. The header's right actions keep their width while a longer filename shrinks, avoiding mobile page overflow in the comparison walkthrough.
